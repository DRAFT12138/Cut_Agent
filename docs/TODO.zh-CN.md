# Cut Agent 下一步工作计划

> 评估基线：`0.2.0`，2026-09-29。本文是按优先级维护的工程 TODO，不是已经承诺的发布日期。

[返回 README](../README.zh-CN.md) · [使用说明](usage.zh-CN.md)

## 1. 当前判断

仓库已经具备一个可用的本地粗剪闭环：素材扫描、文案分段、镜头理解、时间线生成、网络素材与音乐建议、可编辑 Web 工作台、预览、恢复、A/B 版本和交接包。当前 209 个 Python 测试覆盖时间线、帧对齐、缓存、恢复、代理协议和交付等核心逻辑；Web 侧已有类型检查、生产构建和少量文档安全测试。

P0 已经达到本地单用户“能用”的工程基线。下一阶段不再以扩大过渡防御为主，而应把 Cut Agent 的确定性媒体能力暴露给 Codex、Claude Code 等编码代理，让代理直接查看素材、生成决策并驱动粗剪，无需单独配置模型 API。

- 编码代理擅长查看文件、图片和结构化上下文，但现有流水线只接受 OpenAI 兼容接口或规则降级，无法直接接收代理做出的高质量分段和镜头选择。
- 第一阶段采用可审查、可重复的 JSON 文件协议；等协议经过 Codex 与 Claude Code 实际使用后，再决定是否包装为 MCP 工具。
- 诊断、全面 schema 和模块拆分改为按真实故障推进，不再阻挡用户可感知的能力迭代。

## 2. 优先级与完成定义

- **P0（发布门槛）**：不完成就不建议发布下一个版本。
- **Next（当前主线）**：向 Codex、Claude Code 暴露稳定工具和 Skill，以编码代理取代模型 API。
- **按需可靠性**：只在真实故障或安全边界要求出现时推进。
- **功能与质量**：优先提升剪辑效率、代理方案质量和实际交付价值。

每项只有在代码、自动化验证和用户文档同时更新后才算完成；若改变 `plan.json` 或阶段产物，必须包含旧任务兼容或迁移测试。

## 3. P0 — 建立可发布基线

### P0.1 持续集成与测试分层

- [x] 新增 CI，固定执行 Python 3.10 与 3.14 的单元测试、Web 测试和 Web 生产构建。
- [x] 在媒体测试任务中显式安装并记录 FFmpeg/FFprobe 版本；将不依赖媒体二进制的快速测试与真实编解码测试分开。
- [x] 为缺少 FFmpeg/FFprobe 的场景提供明确的 skip/预检提示，避免几十个同因失败掩盖真实回归。
- [x] 加入 Python 静态检查和增量格式检查；存量代码的全量格式化留待独立提交，避免与功能修改混杂。

**验收：** 新检出仓库可通过一条文档化命令运行快速检查；CI 能运行完整 Python 测试、Web 测试和构建，并能清楚显示媒体测试是否执行。

### P0.2 可安装、可复现的发行物

- [x] 将预构建 Web 资产嵌入 Python wheel/sdist，不再依赖源码仓库相对路径。
- [x] 增加 wheel/sdist 构建测试：在空虚拟环境安装产物，运行 `cut-agent --help`、启动服务并请求首页与 `/api/stages`。
- [x] 以 Python 包版本为运行时事实源，并用发布检查核对 Python 与 Web 版本及发行内容。
- [x] 写明支持 Linux、Windows 与 FFmpeg/FFprobe 5+，并在 CI 验证两个系统的隔离安装路径。

**验收：** 用户无需克隆源码或手工构建 Web，就能从发行物启动完整工作台；发布测试不读取仓库内的 `web/dist`。

### P0.3 关键 Web 流程自动化

- [x] 将现有分散的 `tools/verify_*_ui.py` 整理为统一入口，并区分冒烟、回归、外部服务三类套件。
- [x] 将“新建任务 → 查看阶段 → 编辑时间线 → 重建预览 → 下载交接包”的既有离线验证统一纳入浏览器套件入口。
- [x] 回归套件覆盖暂停/恢复、服务重启、跨标签编辑冲突和 A/B 比较；统一入口保留截图及每个脚本的合并日志。
- [x] 把无外网 Chromium 冒烟用例接入 CI，外部搜索和真实模型用例保留为可选任务。

**验收：** 一条命令可在本机复现核心用户旅程；CI 至少执行无外网冒烟套件，并上传失败证据。

## 4. Next — 编码代理工具与 Skill（当前主线）

### N1 文件式工具协议

- [x] 新增 `agent-context`，把文案、素材元数据、代表帧路径和决策契约导出为稳定 JSON。
- [x] 新增 `--agent-decisions`，让外部代理提供分段、素材描述、时间线和配乐决策，并绕过对应的模型 API 调用。
- [x] 在运行前验证 schema、必填字段、未知字段和素材引用；保留现有时间线清洗、自检、预览与交付链路。
- [x] 升级 v2 契约：稳定 `media_id` / `segment_id`、代表帧时间点、原文完整覆盖、每段唯一覆盖和视频源范围校验。
- [ ] 增加基于既有 run 的“导出上下文 → 修改决策 → 重建”工具，避免每次修改都新建完整任务。

### N2 Codex / Claude Code Skill

- [x] 提供仓库内 `cut-agent-rough-cut` Skill，规定素材查看、决策生成、离线执行和结果复查流程。
- [x] 提供紧凑的 decision JSON 参考，明确精确文件名、旁白文本和源时间范围约束。
- [ ] 用同一固定样例分别由 Codex 与 Claude Code 完成端到端粗剪，记录失败点并收紧 Skill。
- [ ] 评估在文件协议稳定后增加 MCP server；MCP 只封装稳定工具，不复制流水线业务逻辑。

**验收：** 未配置 `CUT_AGENT_LLM_*` 时，编码代理能查看代表帧、生成有效决策、完成预览与交接产物；同一 decisions 文件可重复执行和审查。

## 5. 按需可靠性 — 出现真实问题后推进

### P1.1 运行前检查与诊断包

- [ ] 新增 `cut-agent doctor`：检查 Python、FFmpeg/FFprobe、Web 资产、输出目录权限、模型接口、Chrome 和可选搜索服务。
- [ ] 将检查结果分为必需、可选、降级三类，并在新建任务前复用同一套后端检查。
- [ ] 提供脱敏诊断包，包含版本、配置项是否存在、阶段状态和最近错误，不包含 API Key、文案、媒体或浏览器 cookie。
- [ ] 为模型超时、媒体损坏、磁盘空间不足、外部下载失败建立稳定的错误码与恢复建议。

**验收：** 常见配置问题可在启动任务前发现；用户提交诊断包即可定位失败阶段，同时自动化测试证明敏感信息不会进入包内。

### P1.2 产物契约与恢复兼容

- [ ] 为 `run.json`、`plan.json`、阶段产物和事件定义显式 schema/version，并在读写边界验证。
- [ ] 建立从 `0.2.x` 产物升级的 fixture，覆盖旧任务读取、编辑、恢复、重建和交接导出。
- [ ] 明确原子写入、缓存损坏、进程崩溃和并发编辑的恢复矩阵；每种情况至少有一个测试。
- [ ] 为长任务增加可观测指标：阶段耗时、缓存命中、重试次数、降级原因和产物大小。

**验收：** 新版本能打开约定支持范围内的旧任务；不兼容数据会给出可操作错误，而不是部分覆盖或静默生成错误结果。

### P1.3 拆分高耦合模块

- [ ] 按“阶段节点 / 降级策略 / 产物序列化”拆分 `graph.py`，保持节点输入输出契约不变。
- [ ] 按“生命周期 / 执行器 / 状态查询 / 恢复”拆分 `runs.py`，集中锁与状态迁移规则。
- [ ] 将 `App.tsx` 中的数据获取、路由状态和页面布局拆成独立 hooks/组件，避免页面级状态继续膨胀。
- [ ] 重构前先补契约测试；重构提交不得同时改变用户行为。

**验收：** 核心模块职责边界可由测试说明；阶段和运行状态迁移只有一个实现入口，现有回归套件全部保持通过。

### P1.4 本地服务安全边界

- [ ] 明确默认仅绑定回环地址；绑定非本机地址时显示风险提示，并设计可选认证机制。
- [ ] 对文件读取、媒体替换、下载文件名和任务 ID 做统一路径边界验证与审计测试。
- [ ] 为外部 URL 获取补充重定向后的 SSRF 检查、大小/时长限制、MIME 校验和超时策略。
- [ ] 将威胁模型、隐私数据流和漏洞报告范围补入安全文档。

**验收：** 路径穿越、非预期本地文件读取、危险重定向和超大下载均有负向测试；默认配置不暴露到局域网。

## 6. 功能迭代 — 提高剪辑效率和输出质量

### P2.1 时间线编辑能力

- [ ] 增加多选、批量时长调整、撤销/重做和键盘操作。
- [ ] 对拖拽、替换和重建显示未保存状态与冲突解决，而不是只依赖请求完成提示。
- [ ] 增加语音时长输入或旁白音轨导入，使镜头时长不再主要依赖中文字符数估算。
- [ ] 评估导出 FCPXML、EDL 或 OTIO；先选一种真实剪辑软件做往返验证。

**验收：** 使用一套固定样例完成编辑所需操作数可量化下降；导出的交换格式能在目标软件正确还原顺序、入出点和静帧时长。

### P2.2 方案质量评测

- [ ] 建立不含私人素材的小型黄金数据集，覆盖横屏、竖屏、旋转、VFR、图片、短素材和素材不足。
- [ ] 定义分段完整率、镜头重复率、素材覆盖率、越界率、降级率和人工修改量等指标。
- [ ] 对规则降级、模型方案和不同 seed 做同一套离线评测，不只比较文案观感。
- [ ] 记录提示词、模型和配置版本，使回归结果可解释；禁止把真实 API Key 或模型响应原文提交到仓库。

**验收：** 每次调整规划/匹配算法都能输出基线对比报告，并为关键指标设置回归阈值。

### P2.3 性能与资源治理

- [ ] 用 10、100、1000 个素材和长视频建立扫描、抽帧、缓存、预览基准。
- [ ] 限制并发媒体进程、下载大小、缓存总量和单任务磁盘占用，并提供清理/保留策略。
- [ ] 优化 Web 首包；当前应优先做路由/重组件懒加载，再评估依赖替换。
- [ ] 为取消、暂停和服务退出增加子进程清理测试，避免遗留 FFmpeg/浏览器进程。

**验收：** 发布说明记录基准机器与数据规模；资源超限会受控降级或失败，且不会破坏可恢复产物。

## 7. 后续扩展 — 有数据后再决定

- [ ] 项目级素材库、标签与跨任务复用。
- [ ] 可插拔模型/搜索/音乐提供方，并提供能力探测而非供应商硬编码。
- [ ] 团队协作与远程部署；启动前先完成鉴权、权限、存储隔离和审计设计。
- [ ] 字幕、配音、调色或直接成片能力；只有在“不取代精剪交接”的产品边界被重新确认后再立项。

这些项目暂不进入当前里程碑。尤其不要在 P0/P1 完成前开放公网部署或多人写入同一任务。

## 8. 建议里程碑

| 里程碑 | 范围 | 可交付结果 |
| --- | --- | --- |
| M1：绿色基线 | P0.1 | 分层测试与 CI，媒体依赖结果清晰 |
| M2：可发布安装 | P0.2 + P0.3 | 可安装工作台、发行物冒烟、核心浏览器流程 |
| M3：代理粗剪 | N1 + N2 | Codex/Claude Code 无模型 API 完成粗剪 |
| M4：可靠任务（按需） | 原 P1.1 + P1.2 | doctor、诊断包、schema 与旧任务兼容 |
| M5：编辑效率 | 从功能迭代中选一个经数据验证的项目 | 可量化的操作、质量或性能改善 |

每个里程碑结束时更新本页：勾选已完成项，链接对应测试或设计文档，并根据用户反馈重新排序未完成项。新工作默认优先评估编码代理与用户功能价值；只有数据丢失、安全风险或发布阻断继续作为工程插队项。
